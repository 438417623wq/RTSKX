## 二、这一期实际做出来的东西

### 2.1 新增文件

| 文件 | 作用 |
|---|---|
| `assets/scripts/Settings.gd` | 全局设置：`DEFAULTS` 表 + ConfigFile 持久化 + 类型化读取 |
| `tests/Menu.gd` | 菜单与设置的无头验证，**63 条断言** |

### 2.2 `Settings.gd` 的三个设计决定

1. **只放真的生效的项。** 放一个「有开关但没人读」的装饰项，玩家会当成 bug（点了没反应）—— 那比没有这个开关更糟。
2. **未登记的键必须报错，且只报一次。** 少写一个默认值的症状是「读回 null、写不进去、页面照样画得出来」——完全静默。
   ⚠️ 只报一次是必须的：未登记的键会在**每帧绘制**里被读到。不设闸门就是刷屏，而刷屏的后果是**真正的错误被埋掉**。
   （实测：局域网页的 `lan_ip` 漏登记，截一次图刷了 9 条 ERROR。）
3. **存盘走 `user://settings.cfg`**，安卓落在 `Android/data/<包名>/files/settings.cfg`，卸载即清。

### 2.3 通用表单渲染器

菜单从「一层平铺」改成「**一页 = 一份数据 + 一个渲染器**」：

```
页面描述 { title, subtitle, layout, tabs?, primary?, sections[ {name, items[]} ] }
item.kind ∈ { tile, button, choice, toggle, slider, text, label }
```

**加一项设置 = 加一行数据**。排版、命中、绘制三边都从同一份描述算出来。

### 2.4 菜单结构

```
HOME（2×2 卡片）
├─ SINGLE   阵营 3 / 难度 3 / 地图 3 / 速度 3 + 开始战斗
├─ LAN      玩家名 / 创建房间 / 主机地址 / 加入房间 + 使用说明
├─ SETTINGS 5 个分类 tab：画面 / 音频 / 操作 / 游戏 / 界面
└─ MODS     已安装列表（只读）+ 模组目录
```

页面导航用**页面栈**而不是单变量：模组页将来要能弹出「导入确认」再退回来，单变量会一路退回主菜单。
⚠️ **切 tab 不进页面栈** —— 它是「换内容」不是「换页」，否则连点 5 个 tab 后要按 5 次返回。

### 2.5 真正接线生效的设置

| 设置项 | 生效点 |
|---|---|
| `max_fps` | `Engine.max_fps` |
| `show_fps` | `_draw_fps()`，画在顶栏下方靠右 |
| `sfx_on` / `sfx_volume` | `_sfx_on` / `_sfx_volume` |
| `drag_pans` | 单指拖动语义（平移视野 / 框选部队） |
| `long_press` | 长按框选阈值（`const LONG_PRESS` 改成 `var long_press`） |
| `minimap_jump` | 点小地图是否跳转镜头（**按住拖动仍能拖镜头**，这是显式操作） |
| `default_difficulty` / `default_map` / `default_speed` | 下一局初值 |
| `autopause` | `start_game()` 里的 `paused` |

## 三、★这一期最重要的收获：一条**假绿**的测试★

### 3.1 症状

设置页 12 个设置项排成一条列表时，面板算出来高 **858px**，而屏幕只有 **720px**。
「默认速度 / 开局自动暂停 / 恢复默认」整块被推出屏幕 —— **而 46 条断言全绿**。

### 3.2 根因（两层，第二层才是关键）

**第一层：断言选错了对象。**
原来的断言是「逐个查可点项在不在屏幕内」。而「恢复默认」是按**面板底边**定位的 ——
面板自己溢出屏幕时，它一个项都不在屏内，**反而没得查**。
👉 正确判据是查**面板本身**：`_form_metrics()` 的 `panel.end.y <= vp.y`。

**第二层：测试量错了视口。**
headless 下 `get_viewport_rect()` 返回的是 **1280×1280**（正方形），
而 `project.godot` 写的是 **1280×720**、`shots/` 下 32 张截图也全是 1280×720。
👉 测试一直在那个**虚高的 1280** 上验，真机的 720 从来没被验过。

### 3.3 修法与防复发

1. 新增 `DEVICE_SIZES` 表，**显式传真机分辨率**（`menu_hit_table(vp)` / `_form_metrics(vp, desc)` 都是纯函数，不需要真的改窗口尺寸）。
   - 硬要求 `1280×720`（`stretch/mode=canvas_items` + 默认 `aspect=keep` ⇒ 真机逻辑视口恒为此值）
   - 另加 4 档**更高**的分辨率（平板 / 将来若改 `aspect=expand`）
2. 设计上把设置页从「一条长列表」改成 **5 个分类 tab**，单 tab 最多 4 项。
   ⚠️ **不能靠压行高解决**：行高 46 已是触控下限，压到能装下（约 30px）就低于 Android 48dp 建议值了。
3. 断言**逐 tab 验一遍** —— 分类之间项数不一样，最长的那个才决定高度。

> 📌 **纪律：凡是「装不装得下」的断言，一律不能用 `get_viewport_rect()`。**
> 已写进 `tests/run_all.sh` 的注释。

## 五、诚实的缺口

### 5.1 矮于 720 的屏幕装不下局域网页

实测 **1024×600** 时局域网页面板高 550、底边落在 **610 > 600**。

- 行高 46 已是触控下限，压到 38 也仍装不下（固定开销 274 + 6 行）
- 真要支持矮屏得**加滚动**或**砍掉分组标题** —— 属于 M2 之后的事
- 📌 **没有写一条假装通过的断言**：`DEVICE_SIZES` 里没有 1024×600，缺口如实记在 `tests/Menu.gd` 的注释里

> 实际上 `aspect=keep` 让真机逻辑视口恒为 1280×720，所以这个缺口**当前不会触发**。
> 但一旦有人把 `aspect` 改成 `expand`（移动端常见选择），它就会暴露。

## 六、验证与验收

### 6.1 自动化

```bash
bash tests/run_all.sh          # 11 套快速套件
```

> 🔧 **顺手修了 `run_all.sh` 的一个真问题**：原来用管道接 Godot 的 stdout
> （`... | grep -vE ...`），而 stdout 一旦被管道接住就变成**块缓冲** ——
> 套件没退出之前一个字节都不刷。症状是「跑了很久一行输出都没有」，
> **看起来完全像死循环**（本项目因此误判过一次「Economy 卡死 6 小时」，
> 实际是机器休眠 + 缓冲叠加；单独跑实测 74/74 通过、用时 326 秒）。
>
> 改成重定向到文件（`> /tmp/wb_test_X.log 2>&1`）：避开缓冲、
> 能 `tail -f` 看进度、还能直接用 `$?` 而不用 `PIPESTATUS`。
> 另加每套件 `timeout`（默认 900s，`TIMEOUT=` 可覆盖）——
> **死循环比失败更糟**：失败会报错，死循环只会让人干等。
