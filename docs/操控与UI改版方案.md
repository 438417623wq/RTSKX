## 二、P0：建筑放不下去（必须先修）

### 根因

`_on_touch()` 用**屏幕纵向位置**来判断一次触摸是不是 UI 操作：

```gdscript
# Main.gd:590
if pos.y > panel_top or pos.y < TOP_H:      # panel_top = vp.y - PANEL_H = 580
    _ui_press_id = index
    ...
    return
```

只有落在这个区间里的触摸，松手时才会调用 `_handle_ui_click()`，
而 `_build_choices`（建造菜单条目）**只在那里被检查**。

但建造菜单是画在面板**上方**的浮层：

```gdscript
# Main.gd:1225
if _build_menu_open:
    _draw_build_menu(pr.position.y - 8.0)    # 572 起，向上展开
```

实测（`tests/_diag_place.gd`，1280×720）：

```
_build_choices 条目数 = 4
   supply_depot   y=514..560  ★面板外（点不到）
   refinery       y=514..560  ★面板外（点不到）
   barracks       y=514..560  ★面板外（点不到）
   factory        y=514..560  ★面板外（点不到）
该点会被路由到 _handle_ui_click 吗？ false
真实触摸后 _placing_build = ''          ← 没进入放置模式
_handle_ui_click 后 _placing_build = 'barracks'   ← 直接调用则正常
```

**所以：点建造菜单 = 被当成点地图**。不但不会进入放置模式，
还会给选中的农民下达一条移动指令到那个位置——这就是"放不下去"。

顺带：`_do_tap_command()` 里完全没有 `_build_choices` / `_quick_buttons` /
`_cmd_buttons` / `_train_buttons` 的处理，它只认"世界坐标"。

### 修法（架构级，一次解决这类 bug）

**废弃「靠 y 坐标猜是不是 UI」的做法，改成显式的 UI 命中注册表。**

```gdscript
# 每帧由各 _draw_* 重建
var _ui_hits: Array = []          # [{rect, act, arg}]

func _ui_pick(p: Vector2) -> Dictionary:
    # 后画的在上层，所以倒序找
    for i in range(_ui_hits.size() - 1, -1, -1):
        if _ui_hits[i]["rect"].has_point(p):
            return _ui_hits[i]
    return {}
```

`_on_touch()` 按下时：

```gdscript
var hit := _ui_pick(pos)
if not hit.is_empty():
    _ui_press_id = index
    _ui_press_hit = hit
    return
```

各绘制函数把可点区域登记进去即可（`_add_cmd_button` / `_build_choices` /
`_train_buttons` / `_queue_buttons` / `_group_buttons` / 小地图 / 顶栏按钮）。

**收益**：以后任何位置的弹窗、悬浮按钮、技能栏都自动可点，
不会再出现"画出来了但点不到"。

### 附带要修的

- `_start_placing()` 之后，`_placing_build` 生效期间应当**屏蔽地图点击的其它语义**，
  当前靠 `_do_tap_command()` 开头一句 `if _placing_build != "": return` 兜着，
  改成命中表后逻辑更清楚。
- 放置失败时 `cmd_build` 会 `event_alert` 弹提示，这条链路是通的（已验证），保留。
- 建议加**放置失败原因就地显示**：幽灵框变红的同时，在框下方直接写原因
  （现在只有顶部 toast，手指挡住时看不见）。

## 三、P1：操控方式（滑动拉视野）

### 现状

| 手势 | 现在的行为 |
|---|---|
| 单指拖动 | 框选 |
| 双指拖动 | 平移镜头 |
| 双指捏合 | 缩放 |
| 小地图点/拖 | 跳转 |

（这套其实是《铁锈战争》的方案，但双指平移在手机上并不好用。）

### 建议方案

**把「单指拖动」的语义做成可切换项，默认改为平移视野：**

| 手势 | 新行为 |
|---|---|
| **单指拖动** | **平移视野**（默认） |
| **长按 0.25s 后拖动** | **框选**（保留框选能力，起手有震动/高亮反馈） |
| 单指轻点 | 选择单位 / 下达指令 |
| 双指拖动 | 平移视野（保留，习惯双指的人照用） |
| 双指捏合 | 缩放 |
| 小地图点 / 拖 | 跳转 / 连续拖动镜头 |
| 双击 | 全选同类 / 全屏 |

**为什么用「长按后拖动」而不是别的**：
- 不需要新增模式按钮，不打断操作节奏
- 单指拖动是平移（高频、要求即时响应），长按框选（低频、可以多花 0.25 秒）
- 按下后若 0.25s 内移动超过阈值 → 直接判定为平移；否则进入框选
  （即"先动 = 平移，先停 = 框选"，符合直觉）

**同时提供设置项**（游戏内设置面板）：
```
单指拖动： [ 平移视野 ]  [ 框选 ]      ← 默认平移视野
长按框选： 开 / 关                      ← 关掉则只能靠设置切换
镜头惯性： 开 / 关                      ← 松手后短暂滑行，手感更顺
```

**实现要点**
- `_on_touch` 按下时记录 `start` + `time`，进入 `Sel.PENDING`
- `_on_drag` 里：若 `PENDING` 且位移 > 12px 且未超 0.25s → 转为 `Sel.PAN`；
  若超 0.25s 仍未动 → 转为 `Sel.BOX` 并给一次触觉/视觉反馈
- 平移量：`cam_pos -= rel / cam_zoom`（和现在双指平移一致）
- 松手时 `Sel.PAN` 直接结束；`Sel.BOX` 才做框选

**风险**：老习惯（单指即框选）被改掉，需要给一个明确的首次提示
（进游戏时顶部提示 3 秒："单指滑动移动视角 · 长按拖动框选部队"）。

## 四、P1：建筑图标太小

### 现状

建造菜单条目 `104×46` 逻辑像素，**只有文字没有图标**：

```gdscript
var bw := 104.0
var bh := 46.0
```

以 6.5 寸 2400×1080 屏为例（横屏逻辑 1600×720，缩放 1.5，约 0.094mm/逻辑像素）：
46 逻辑像素 ≈ **4.3mm** —— Android 建议的最小触控目标是 48dp ≈ **7.6mm**，
现状**只有建议值的约 57%**。

### 建议

改成**图标 + 名称 + 造价**的大按钮：

| 元素 | 现在 | 建议 |
|---|---|---|
| 建造条目 | 104×46，纯文字 | **96×84**，图标 48×48 + 名称 + 造价 |
| 训练条目 | 86×46，纯文字 | **80×72**，图标 40×40 + 名称 + 造价 |
| 指令按钮 | 66×30 | **76×56** |
| 编队号 | 44×30 | **52×44** |
| 底部面板高 | 140 | **156** |

上表的建议尺寸按同一块屏换算：建造条目 84 逻辑像素 ≈ **7.9mm**，
刚过 48dp 建议线；指令按钮 56 ≈ 5.3mm（按钮密集，属可接受的折中）；
编队号 44 ≈ 4.1mm（低频操作，且带长按兜底）。

图标直接用**已经烘焙好的建筑/单位贴图**（`TEX["b_xxx"]` / `TEX["u_xxx"]`），
不需要额外美术资源 —— 贴图本来就在内存里。

同时补上：
- **不可建造时**（资源不足 / 缺前置）用灰色 + 角标写缺什么
- **长按条目**弹出该建筑的简介（血量 / 造价 / 前置），避免误建

## 五、P2：布局重构

### 现状（1280×720 逻辑）

```
┌───────────────────────────────────────────────────────────┐
│ 顶栏 34px   矿物/瓦斯/人口        时间    敌基地          │
├───────────────────────────────────────────────────────────┤
│                                            ┌────────────┐ │
│                   战场                     │  小地图     │ │
│                                            │ 172×107    │ │
│  ┌─────────────────┐                       └────────────┘ │
│  │ 建造菜单(浮层)  │  ← 点不到（P0）                        │
│  └─────────────────┘                                       │
├───────────────────────────────────────────────────────────┤
│ 停止 全选 回基地 │ 选中信息              │ 单位头像(右)  │
│ 建造 采矿 攻击移动 全选同类                                │
│ 编队 1 2 3 4 5 6                                           │
└───────────────────────────────────────────────────────────┘
   面板高 140，从 y=580 开始
```

问题：
- 小地图在**右下**、指令在**左下** —— 与 RTS 通用习惯相反
- 右下角（右手拇指最舒服的位置）放的是"编队号"，价值最低
- 建造菜单浮在面板外，游离于命中区之外（就是 P0 的根因）
- 选中信息挤在按钮行里，和按钮抢位置

### 建议（经典 RTS 三段式）

```
┌───────────────────────────────────────────────────────────┐
│ 顶栏 34px   矿物/瓦斯/人口        时间    敌基地          │
├───────────────────────────────────────────────────────────┤
│                                                           │
│                      战场（单指滑动平移）                  │
│                                                           │
│  ┌────────────┐                                           │
│  │  小地图     │  ← 移到左下（左手拇指区）                 │
│  │  172×107   │                                           │
│  └────────────┘                                           │
├───────────────────────────────────────────────────────────┤
│  选中信息行（名称 / 血量 / 状态）              h≈30        │
├──────────────────┬────────────────────────────────────────┤
│ 编队 1..6        │        ┌─────────────────────────────┐ │
│ (左，占 ~330)    │        │  建造 / 训练 / 技能 图标按钮 │ │
│                  │        │  右对齐，向右下角生长        │ │
│                  │        └─────────────────────────────┘ │
└──────────────────┴────────────────────────────────────────┘
   面板高 156，从 y=564 开始
```

要点：
1. **小地图移到左下角**，位于面板之上
2. **指令区固定在右下角**，按钮**从右往左**排（右对齐），
   新增按钮不会把已有按钮挤走
3. **建造菜单从右下角就地展开**（向上/向左），不再是浮在面板外的孤儿
4. 选中信息独立成一行，不再和按钮挤
5. 面板高度 140 → 156（换取更大的触控目标）

**为什么这样分**：横屏双手持机时，右下是右手拇指的自然落点，
高频操作（建造/训练/放技能）都该在那里；
小地图是"偶尔看一眼、偶尔点一下"，放左下不占拇指区。

## 六、P2：音效

### 原则

本项目的美术是**程序化生成**的（零外部素材，零版权风险）。
音效沿用同一条路线：**用代码合成 PCM**，不引入任何音频文件。

### 实现

新增 `assets/scripts/GenSfx.gd`，产出 `AudioStreamWAV`：

```gdscript
static func ui_click() -> AudioStreamWAV      # 短方波，60ms
static func ui_error() -> AudioStreamWAV      # 下行方波，180ms
static func build_start() -> AudioStreamWAV
static func build_done() -> AudioStreamWAV    # 上行三音
static func train_done() -> AudioStreamWAV
static func shot_bullet() -> AudioStreamWAV   # 噪声 + 快速衰减
static func shot_cannon() -> AudioStreamWAV   # 低频冲击 + 噪声
static func shot_laser() -> AudioStreamWAV    # 扫频正弦
static func explosion() -> AudioStreamWAV     # 长噪声 + 低通 + 慢衰减
static func melee_hit() -> AudioStreamWAV
static func unit_death() -> AudioStreamWAV
```

合成要点：
- `AudioStreamWAV`，`FORMAT_16_BITS`，22050 Hz，单声道
- 包络：`env = exp(-t * decay)`，避免爆音
- 音色：正弦/方波 + 单极点低通滤过的白噪声
- 全部在启动时生成一次并缓存（和贴图一样）

### 关键：必须做播放池 + 限流

几百个单位同时开火会直接爆音 + 掉帧。必须：

| 机制 | 做法 |
|---|---|
| 播放池 | 预建 16 个 `AudioStreamPlayer` 轮转复用 |
| 同音限流 | 同一音效最小间隔 0.04s（枪声），0.12s（爆炸） |
| 每帧上限 | 单帧最多触发 4 个 |
| 屏幕外丢弃 | 不在 `_visible_rect()` 内的音效直接不播 |
| 距离衰减 | `volume_db = linear_to_db(clamp(1 - dist/600, 0, 1))` |
| 音量控制 | 设置项：主音量 / 音效音量，默认 70% |

### 接入点

逻辑层不碰音频。`World` 新增一个信号：

```gdscript
signal event_sfx(kind: String, pos: Vector2)
```

在开火 / 命中 / 死亡 / 建筑完工 / 单位出产处 `emit`，
`Main` 负责限流与播放（和现有 `event_alert` 一个套路）。

## 十、实施记录（2026-09-21）

三个待拍板点均按建议执行：单指拖动 = 平移视野（长按框选）、小地图移到左下、
音效包含单位应答音（短促电子哔声）。

### 改动文件

| 文件 | 改动 |
|---|---|
| `assets/scripts/Main.gd` | 输入路由重做 + 手势判定 + 布局重排 + 图标按钮 + 音效播放池 |
| `assets/scripts/World.gd` | 新增 `signal event_sfx(kind, pos)`，在开火 / 命中 / 死亡 / 完工 / 出产 / 开工处 emit |
| `assets/scripts/GenSfx.gd` | **新增**。代码合成 19 个 `AudioStreamWAV` |
| `tests/Touch.gd` | 手势断言改写 + 新增「建造菜单必须可点」回归（38 → 46 项） |
| `tests/Smoke.gd` | 新增音效有效性 + 音效事件发出断言（10 → 12 项） |
| `tests/_diag_place.gd` | 删除（诊断使命完成，结论已固化进 Touch.gd） |

### P0 的最终形态

`_on_touch()` 不再看 y 坐标，改成查每帧重建的命中表：

```gdscript
var _ui_hits: Array = []        # [{rect, act, arg}]，_draw() 里清空，各 _draw_* 登记

func _ui_pick(p: Vector2) -> Dictionary:
    for i in range(_ui_hits.size() - 1, -1, -1):
        if (_ui_hits[i]["rect"] as Rect2).has_point(p):
            return _ui_hits[i]
    return {}
```

按下时命中就记 `_ui_press_hit`，松手走 `_dispatch_ui(hit)` 统一分发。
`_handle_ui_click()` 已删除；`_quick_buttons` / `_cmd_buttons` / `_train_buttons` /
`_queue_buttons` / `_build_choices` / `_group_buttons` 六个数组全部作废（被命中表取代）。

**为了可测性**：建造菜单的布局计算抽成了纯函数 `build_menu_layout(vp)`，
不依赖绘制上下文，所以无头测试也能验证「菜单落在哪、能不能被点到」。

### 手势判定的实现要点

`Sel` 枚举新增 `PENDING` / `PAN`：

- 手指落下 → `PENDING`
- `_on_drag` 里位移 > `PAN_SLOP`(12px) → 按 `_single_drag_pans` 决定进 `PAN` 还是 `BOX`
- `_process` 里轮询 `_update_pending_gesture()`：停够 `LONG_PRESS`(0.25s) → 进另一个分支
  （**手指按住不动时不会产生 drag 事件，所以长按判定必须轮询**）
- 原地抬起 → 轻点

面板左下角「拖动:平移 / 拖动:框选」按钮可随时切换语义。

### 音效的关键约束

播放池 16 个 `AudioStreamPlayer` 轮转 + 同音限流 0.045s + 单帧上限 4 个 +
迷雾外不播 + 620px 距离衰减 + 音高抖动 ±7%。
19 个音效实测合计 **251 KB**，合成耗时约 260–360 ms（启动时一次性）。

### 验证结果

| 项 | 结果 |
|---|---|
| `tests/run_all.sh` | Matchup 12 / Smoke 12 / Economy 74 / Touch 46 —— **142 项，0 失败** |
| 截图肉眼核对 | `shots/` 下 12 张全部正常（含建造菜单、两种面板、帮助页） |
| 导出 PCK 启动 | `[Art] 贴图就绪：36 张（其中外部素材 31 张）` · `[Sfx] 16 个播放通道` |

### 真机待确认（桌面鼠标测不出来）

1. 单指平移的手感 —— 跟手程度、有没有延迟感
