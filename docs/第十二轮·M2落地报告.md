## 二、模型：锚点 + 偏移 + 缩放

改 M2 之前，HUD 的坐标散在 7 个地方硬编码，玩家一个都动不了。现在每个模块是一份四元组：

```gdscript
{"anchor": "bl", "ox": 12.0, "oy": -192.0, "scale": 1.0, "visible": true}
```

模块矩形 = 屏幕锚点 + offset 定位「模块的 pivot 点」，再按 size 展开：

```
pivot = 由 anchor 决定（tl→(0,0)、bc→(0.5,1)、br→(1,1) …）
rect.position = anchor_xy(anchor, vp) + offset - pivot * size
```

**关键取舍：缩放只乘在尺寸上，offset 不乘。** 否则改一下缩放，模块位置也会跟着漂，拖动时手感会突然跳一下。

**缩放只给三档（0.85 / 1.0 / 1.15），不给连续值。** 最小按钮是 `96 × 84`，0.85 档是 81.6×71.4，仍高于触控下限；再往下就破线了 —— 46 逻辑像素在 2400×1080 上只有 4.3mm，不到 Android 48dp 建议值的六成。

### 六个模块与默认值

| 模块 | 锚点 | 偏移 | 尺寸（1.0 档） |
| --- | --- | --- | --- |
| `res` 资源栏 | `tl` | `0, 0` | `vp.x*0.5+90 × 34` |
| `sysbtns` 系统按钮 | `tr` | `-8, 0` | `252 × 34` |
| `minimap` 小地图 | `bl` | `12, -192` | 宽 `min(172, vp.x*0.22)`，高随世界比例 |
| `info` 信息行 | `bl` | `0, -132` | `470 × 48` |
| `queue` 编队/快捷 | `bl` | `0, -33` | `410 × 96` |
| `cmd` 指令区 | `br` | `-12, -33` | `620 × 96` |

### 底板不再是常量，而是推导出来的

`PANEL_H = 180` 从「面板高度」降级成「面板顶边的**默认**位置」。真正的底板由 `info` / `queue` / `cmd` 里**最靠上的那个底行模块**推出来：

```gdscript
static func panel_rect(vp) -> Rect2:
    var top := INF
    for m in ["info", "queue", "cmd"]:
        if not visible_of(m): continue
        if not String(anchor_of(m)).begins_with("b"): continue   # ★判据是锚点，不是位置
        top = minf(top, rect(m, vp).position.y)
    if top == INF: return Rect2()                                 # 全挪走 → 不画底板
    top = clampf(top, vp.y * 0.40, vp.y)                          # 夹一下，别把战场盖死
    return Rect2(0.0, top, vp.x, vp.y - top)
```

⚠️ **判据必须是「锚点」而不是「位置」**：玩家把指令区拖到屏幕上半部时，它的 `position.y` 很小，但锚点若仍是 `br` 就会把底板拉成半屏高。所以改成顶行锚点的模块直接退出推导。

## 三、接线：8 处硬编码全部改读 `HudLayout`

| 函数 | 旧 | 新 |
| --- | --- | --- |
| `_panel_rect` | `Rect2(0, vp.y-180, vp.x, 180)` | `HudLayout.panel_rect(vp)` |
| `_minimap_layout` | `Rect2(12, vp.y-PANEL_H-h-12, w, h)` | `_mod_rect("minimap", vp)` |
| `topbar_button_rects` | `vp.x - 260/202/140/64` | 从 `sysbtns` 模块右边缘往左排 |
| `_draw_topbar` 底板 | `Rect2(0, 0, vp.x, TOP_H)` | `HudLayout.topbar_rect(vp)` |
| `_draw_topbar` 资源栏文字 | 硬编码 `12 / 310 / vp.x*0.5±…` | 全部相对 `res` 模块原点 |
| `build_menu_layout` | `vp.x-12-menu_w, vp.y-PANEL_H-8-menu_h` | `_cmd_right(vp)` + `_panel_rect().position.y` |
| `build_info_layout` | `vp.y - PANEL_H - h - 10` | `_panel_rect().position.y - h - 10` |
| `_draw_hint` | `Vector2(400, …)` + 宽 `vp.x-420` | 填在「编队区右边缘 → 指令区左边界」之间 |

另外三个内容函数（`_draw_unit_panel` / `_draw_building_panel` / `_draw_upgrade_list` / `_draw_building_queue` / `_draw_group_row` / `_draw_quick_row`）的**每一个尺寸都乘了模块缩放**，右对齐的坐标全部改从 `_cmd_right(vp)` 取。

### 两个顺带修掉的隐患

1. **计时与敌基地数不受 `res` 的 visible 开关影响**。它们是战斗关键信息，玩家只想关掉矿物数字时不该连计时一起消失 —— 所以这两个用 `HudLayout.rect("res", vp)`（不看 visible），只有矿物/瓦斯/人口那行才看。
2. **`sysbtns` 隐藏时 `topbar_button_rects` 返回空字典**，`_draw_topbar` 整段跳过。否则会留下四个「画着但点不到」的鬼影按钮。

## 四、编辑模式

入口：**设置 → 界面 → 「编辑 HUD 布局」**。

### 交互

- 按住模块拖动 → **跟手**；松手 → 按模块中心落在 3×3 的哪一格吸附到对应锚点，并贴该格的屏幕边（边距 12px）
- 点模块 = 选中；点空白 = 取消选中
- 工具栏左侧：`恢复默认` / `保存` / `取消`
- 工具栏右侧（选中后出现）：`隐藏/显示` + `小 / 标准 / 大`
- 屏幕上有 3×3 参考线；模块画半透明幽灵框 + 名称 + 实际尺寸 + 左上角拖动柄
- 重叠的模块画**黄色警告描边**，并在工具栏上方给一行提示

### 设计取舍

1. **不做自由摆放，只做吸附。** 手指把 620×96 的指令区对到 ±1px 是不可能的，自由摆放只会让 HUD 越调越乱；而锚点 + 偏移的模型天然适配任何屏幕尺寸（换手机不错位）。
2. **重叠不做硬禁止。** 硬禁止会带来「为什么拖不过去」的困惑，而玩家有时确实想叠一点（比如把资源栏压在小地图上）。
3. **隐藏的模块照常画出来**（灰色）。否则藏起来之后就再也点不到、永远找不回来 —— 这类「操作后无法回退」的 UI 是设计事故。
4. **「保存」只落盘不退出，「取消」落盘回滚后退出。** 两个动作正交，比「保存并退出 / 放弃并退出」更好懂；保存后继续调，再点取消会回到**已保存的那一份**而不是默认。
5. **拖动过程中不换锚点**，只在松手时吸附 —— 否则模块拖过屏幕中线时会「跳」一下。

### 一个必须记住的坑

编辑模式只从菜单进入，那时 `world == null`。小地图模块会退到 `HudLayout` 的兜底比例 **0.625** —— 正好等于本作 64×40 地图的宽高比（1536×960），所以编辑模式里画出来的框和实机一致。**换地图尺寸的话这个巧合就没了。**

| 4 | JSON 往返 + 垃圾输入整份退回默认 + 未知锚点被拒 + 缩放吸附三档 |
| 5 | 隐藏模块 / 底板推导 / 夹取 |
| 6 | 编辑模式：进入、零重叠、工具栏命中表、拖动跟手、吸附、隐藏、缩放、保存、取消回滚 |
| 7 | **阳性对照**：改掉偏移后第 1 组必须失败；手工摆重叠后检测必须报出来 |
| 8 | 结构性：每个模块都有显示名 / 默认布局 / 合法锚点 / 合法缩放 |

**核心设计：第 1 组把旧公式原样抄了一份当参照**（`_ref_panel` / `_ref_minimap` / `_ref_topbar` / `_ref_sysbtns` / `_ref_build_menu`）。这不是「测试跟着实现写」—— 参照是从旧代码搬过来的常量，改实现不会让它自动通过。

⚠️ 视口一律**显式传真机尺寸**（`1280×720` / `1080×2340` / `2340×1080`）。headless 下 `get_viewport_rect()` 是 1280×1280 的正方形，用它算「装不装得下」会全绿。

## 六、★抓到的真 bug：间接判据的假通过★

`tests/Hud.gd` 第一次跑就红了 12 条，根因是一个**真实的布局错位**：

> `HudLayout.DEFAULTS` 里 `info` 的 `oy` 填了 `-180`、`queue` 填了 `-129` —— 这两个数是「**顶边**相对屏幕底边的偏移」。但 `bl` 锚点的 `pivot` 是 `(0, 1)`，也就是**底边**被锚点钉住，`oy` 应该是「**底边**相对屏幕底边的偏移」。
>
> 结果：`info` 整体上移 48px，`queue` 整体上移 96px。

**为什么之前的测试全绿？**

`tests/Touch.gd` 的 74 条断言是**间接判据** —— 它们查的是「建造菜单在不在面板之上」「介绍卡在不在面板之上」。`panel_rect` 是从这三个模块推出来的，模块上移，面板跟着上移，**相对关系没变**，于是 74 条全部假通过。

这正是 `tests/Hud.gd` 存在的理由：**直接比矩形，而不是比相对关系。**

修正后：

```gdscript
"info":  {"anchor": "bl", "ox": 0.0, "oy": -132.0, ...}   # -(180 - 48)
"queue": {"anchor": "bl", "ox": 0.0, "oy": -33.0,  ...}   # -(129 - 96)
```

### 另外两个靠截图才能发现的问题

1. **矮模块的第二行文字溢出框外**。`res` / `sysbtns` 高 34，而名称画在 `+22`、尺寸画在 `+38` —— 尺寸文字跑到框外，压在 3×3 参考线和隔壁模块上。改成高度 < 46 时把尺寸挪到名称右边同一行。
2. 这个只有截图能发现：无头环境调不了 `_draw_*`。

## 八、还没做的（M2 之后的缺口）

1. **建造菜单的展开方向**只做了「上方放不下就翻到下方」，没有跟 `cmd` 模块的象限走完整逻辑。`cmd` 被拖到屏幕中部时，菜单可能盖住战场中心。
2. **编辑模式里改不了「模块内部」的布局**（比如指令区按钮的间距）。当前只支持模块整体。
3. **小地图宽高比的巧合**依赖地图恒为 64×40。将来加非正方形地图预设时，编辑模式的框会和实机不符。
4. 方案第九节那 5 个待拍板项（局域网路线 / 大厅形态 / 模组是否允许脚本 / HUD 编辑档位 / 是否留「载入存档」入口）仍未定 —— 但 M2 不依赖它们。
