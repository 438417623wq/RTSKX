# 第八~十一轮 · 7 小时推进方案

> 目标：继续往星际争霸 1 靠。**7 个时段，每段 1 小时**，每段结束必须留下一个可验证的产物。
> 本方案基于对当前代码的实际盘点，不是凭记忆写的 —— 两个关键发现见「现状盘点」。

---

## 一、现状盘点

### 已经能玩的（本轮不动）

| 系统 | 状态 |
|---|---|
| 三族 / 15 单位 / 18 建筑 | ✅ |
| 战争迷雾 + 小地图 + 编队 + 框选 + 触屏手势 | ✅ |
| 建造 / 采集 / 生产队列（含本轮的派工修复） | ✅ |
| 科技升级 9 线 25 级 + 3 个技能（兴奋剂 / 攻城模式 / 治疗） | ✅ |
| 代码合成音效（16 路播放池 + 限流） | ✅ |
| 建造介绍卡 / 两行信息行 / 建造者可视化 | ✅ |
| 8 套测试 + 平衡对局 | ✅ |

### 缺口（按「对『像星际』的贡献」排序）

| # | 缺口 | 现有基础设施 | 量级 |
|---|---|---|---|
| 1 | **空中维度**：飞行单位 / 对空对地 / 防空建筑 | 只有 `mutalisk` 一个名字，**没有 `flying` 标记**；`find_nearest_enemy()` 不区分空/地 | 大 |
| 2 | **高地 / 悬崖 / 坡道** | `Grid.Terrain` 有 `CHASM` 枚举，但**全项目只在 `Main.gd:982` 的小地图渲染里用过一次** —— 没有高低差、没有视野/命中加成、寻路不认识坡道 | 大 |
| 3 | **虫族菌毯** | 完全没有 | 中 |
| 4 | **对局外围**：地图选择 / 游戏速度 / 暂停 / 音量 | 菜单只有「种族 + 难度」；顶栏只有一个音效开/关 | 中 |
| 5 | 存档 / 重播 | 完全没有 | 大（本轮不做） |

### ⚠️ 两个必须提前说清的风险

**风险 1：防空建筑需要一整套「建筑能开火」子系统，现在一行都没有。**
`Building.gd` 里没有 `damage` / `cooldown` / 任何攻击函数，`World` 也没有驱动建筑开火的循环。
这不是「加个字段」，而是要把单位那套索敌 / 开火 / 弹道 / 伤害结算在建筑上再实现一遍。
**H2 是本方案里最不确定的一段。**

**风险 2：高低差会让平衡测试的方差变大。**
低地打高地 miss、高地视野加成都会让单局结果更随机。方案里已经把「多局取中位数」列为硬性要求。

## 三、逐时段展开

### H1 · 空中维度：数据与规则

**目标**：把「空 / 地」变成数据，先不碰玩法逻辑。

**改动**
- `GameData.gd`
  - 每个单位加 `attack_air` / `attack_ground`（缺省：地面单位 `attack_ground: true`、`attack_air: false`）
  - `mutalisk` 加 `flying: true`、`attack_air: true`
  - 按星际 1 补齐能打空中的：**陆战队员、刺蛇、龙骑士、执政官**。
    狂热者 / 跳虫 / 蟑螂 / 劫掠者 / 秃鹫 / 攻城坦克 / 医疗兵 / 三个农民 —— 都不能
  - 三族各补 1 个**空中单位**（虫族已有飞龙）：
    人族**幽灵战机**、神族**侦察机**
  - 三族各补 1 座**防空建筑**：
    人族**导弹塔**、虫族**孢子菌落**（只对空）、神族**光子炮台**（对空 + 对地）
  - 全部补 `desc`（上一轮建立的规矩：新内容必须带介绍）
- `Unit.gd`：`is_flying()` / `can_hit(target)`
- `Building.gd`：`can_hit(target)`

**验收**：`tests/Air.gd` 第一组 —— 数据自洽：
不存在「空中单位打不到地面」这种死配置；能打空中的单位确实存在；
防空建筑必须能打到空中；所有新内容都有 `desc`。

---

### H2 · 建筑开火子系统 + 对空/对地索敌 ★最高风险

**目标**：防空建筑真的能打；地面近战**不会**去追飞机。

**改动**
- `Building.gd` 加 `cooldown` / `attack_timer`；`World._update_buildings()` 驱动
  （伤害结算复用 `GameData.compute_damage()`，弹道复用现有的 `projectiles` 数组）
- `World.find_nearest_enemy(from, owner, radius, attacker)` 加**攻击方能力过滤**
- `_update_combat()` 的索敌 / 开火 / 弹道全部按 `can_hit` 过滤
- `attack_move`（攻击移动）同理

**为什么这条最容易出 bug**
漏掉能力过滤的症状极具误导性：**整队跳虫会追着一架飞龙绕地图跑，而且永远追不上** ——
看上去像「AI 变傻了」，其实是索敌没过滤。这个项目已经三次因为
「没有断言过某个量」而让 bug 活很久，所以这条**先写测试**。

**验收**：`tests/Air.gd` 第二组 —— 地面近战打不到空中 / 对空单位能打到 /
防空建筑能打到 / 空中单位不会被地面近战锁住。

---

### H3 · 空中移动、碰撞分层与渲染

**改动**
- `World`：飞行单位**直线移动**（不寻路），忽略 `grid.blocks`（岩石 + 建筑占位），只 clamp 到地图内
- `_separate()` 分层：空 vs 空互推（保持队形）；**空 vs 地不互推**
- 采集 / 建造 / 治疗这些地面逻辑，飞行单位一律不参与
- `Main._draw_world()`：飞行单位**排在所有地面单位之后**绘制（自然叠在上层）；
  阴影**偏移 + 缩小**（表示高度）；选中圈 / 血条位置相应上移
- AI：敌方有空军时会造防空；会派空军骚扰矿点

**验收**：`tests/Air.gd` 第三组 + `bash tests/run_all.sh full` 全绿
+ 截图 `17_air_units` / `18_anti_air`

---

### H4 · 地形高低差：网格与寻路

**改动**
- `Grid` 加 `elevation: PackedByteArray`（0 = 低地，1 = 高地）
- 地图生成器产出**高地平台 + 坡道**（坡道是高低地之间唯一的可通行连接）
- 寻路：地面单位只能通过坡道上下；飞行单位无视高低差
- 建造规则：建筑必须建在**同一层**（不能跨悬崖）
- 迷雾：低地看不到高地（`update_visibility()` 加高度遮挡）

**验收**：`tests/Terrain.gd` 第一组 —— 低地单位绕行坡道 / 飞行单位直线穿越 /
跨层建造被拒 / 低地看不到高地上的敌人

---

### H5 · 地形高低差：战斗加成与渲染

**改动**
- 战斗：**高地打低地 +1 视野、+1 射程**；**低地打高地 30% miss**
- 渲染：高低地明暗分界 + 岩壁侧面 + 坡道纹理；小地图区分高低地
- AI：会把防守部队摆上高地

**验收**：`tests/Terrain.gd` 第二组 + 截图 `19_high_ground` / `20_ramp` + 平衡回归

---

### H6 · 虫族菌毯

**改动**
- `Grid` 加 `creep: PackedByteArray`；虫巢 / 孵化池向外扩散（带半径上限与边缘衰减）
- 规则：**虫族建筑（除虫巢）必须建在菌毯上**；虫族单位在菌毯上移速 +30%；
  菌毯不阻挡任何东西（含地面单位寻路）
- 渲染：紫黑半透明覆盖层，边缘用已有的 `GenTex` 程序化纹理做有机感
- AI：先铺菌毯再扩张

**为什么可行**：神族「建筑必须在水晶塔能量场内」已经有一套现成范式
（`World.power_sources()` / `POWER_RADIUS`），菌毯照抄这套结构即可。

**验收**：`tests/Creep.gd` + 截图 `21_creep`

---

### H7 · 对局外围 + 收尾

**改动**
- 菜单加**地图选择**（3 张预设：开阔平原 / 双坡道高地 / 中间河道）
- 菜单加**游戏速度**（1× / 1.5× / 2×）
- 顶栏加**暂停**；帮助页加**音量滑块**
- 重打 APK、更新 `build/安装说明.txt`、更新记忆与文档
- 全量回归 + 平衡

**验收**：`run_all.sh full` 全绿 + APK 产物

## 四、需要你拍板的四个点

### 1. 防空建筑要不要「同时能打地面」？
- **推荐**：人族导弹塔 / 虫族孢子菌落**只对空**，神族光子炮台**对空 + 对地**（和星际 1 一致）
- 好处：三族有差异，神族防守更强但要更贵
- 另一选项：三座都只对空（更简单，但三族防空完全一样，没意思）

### 2. 三族各补的空中单位要不要「专精」？
- **推荐**：都能对空对地，但定位不同 ——
  人族幽灵战机（快 / 脆 / 便宜）、虫族飞龙（中等 / 弹射溅射）、神族侦察机（贵 / 硬 / 慢）
- 另一选项：只做人族的对空型，把神族留到下一轮（省时间，但三族不对称）

### 3. 高低差的「低地打高地 miss」要不要做？
- **推荐**：做，固定 30%，**只在有高低差时生效**
- 这是星际 1 最有辨识度的规则之一，但会让平衡测试方差变大（必须多跑几局）
- 另一选项：只做「高地 +1 视野 / +1 射程」，不做 miss（方差小，但少了那个味道）

### 4. 菌毯要不要约束「虫族建筑必须建在菌毯上」？
- **推荐**：要。这是虫族的核心约束（对标神族的水晶塔能量场）
- 代价：AI 的扩张顺序要改，H6 时间会紧

## 五、验证纪律（每个时段都适用）

1. 改完先 `--check-only --script res://xxx.gd` 过一遍 —— 能抓 Parse Error /
   未声明标识符 / 类型推断失败，比开窗口跑截图便宜得多
2. 逻辑测试加 `--headless`；**画面验证必须开窗口**跑 `tests/Shot.gd`
3. **每个里程碑结束跑一次 `run_all.sh full`**（含平衡对局，每组合多局取中位数）
4. 新玩法**先写测试再写实现**，至少同步写
5. **平衡基线已变**：本轮的时长基线被建造系统改写（157 / 169 / 158s），
   **不要拿旧的 222 / 212 / 138s 做对照**
