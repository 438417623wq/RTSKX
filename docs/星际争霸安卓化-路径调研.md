## 一、结论先行

三条看似可行的路全部堵死，最终选定 **Godot 4 + GDScript 自研 2D 仿星际 RTS**。

| 路径 | 结论 | 致命问题 |

| Winlator / Box64 跑原版 | ❌ 排除 | 必须外接键鼠；产出是 Wine 容器而非 APP |

## 二、被排除路径的证据

### 2.1 Winlator / Box64（跑原版星际）

- 能力上限：能跑《星际争霸：母巢之战》1.16.1。
- **但**：Winlator 是 Wine + Box64 的安卓前端，本质是"在手机上模拟 Windows"，操作依赖鼠标右键、编队热键、Shift 队列。
- 触屏无法还原这套操作，且产出物是一个模拟器容器，不是可以上架的应用。
- 结论：适合"能在手机上玩原版"的怀旧需求，**不适合做成产品**。

### 2.2 OpenRA 路线（该领域最大的误判）

- OpenRA 是用 C#/.NET 重写的 RTS 引擎，**官方支持的游戏只有 Westwood 系**：红警 1/2、泰伯利亚黎明/之日、沙丘 2000。
- 社区移植的 `franktfye/OpenRA-android` 同样不支持星际，作者明确要求外接键鼠。
- **常见误判链条**：看到"OpenRA 有安卓版" → 以为"能跑 RTS 就能改造星际" → 实际引擎的数据定义、寻路、建造逻辑全是按 Westwood 游戏写的，改造成星际等于重写引擎。
- 结论：**排除**。这是本次调研中最重要的一个排雷。

### 2.3 ScummVM 路线

- ScummVM 是冒险游戏（AVG）解释器，兼容列表里没有任何暴雪游戏。
- 引擎架构是"脚本虚拟机 + 2D 场景"，没有单位、没有寻路、没有 RTS 的任何概念。
- 结论：**直接排除**。

---

## 三、关键参考资产：OpenBW

`github.com/OpenBW/openbw` —— C++ 写的星际 1 **无头模拟器**，复刻了原版的寻路、碰撞、建造队列、指令系统。

- **价值**：读它的代码来理解"原版到底是怎么算的"，尤其是寻路失败回退、单位卡位、建造队列推进这些细节。
- **不能做的事**：它**没有渲染**，不能编译成 APP，也不能直接搬代码（授权与工作量都不合适）。
- 用途定位：**规则参考手册**，不是代码基座。

## 四、为什么是 Godot 4

| 维度 | Godot 4 | Unity |
|---|---|---|
| 授权 | MIT，完全免费，无收入门槛 | 个人版条款有变动史 |
| 2D 能力 | 原生 2D 管线，轻量 | 2D 是 3D 的简化，偏重 |
| 移动端包体 | 空项目 APK ~28MB | 空项目 ~50MB+ |
| 安卓导出 | 内置，一条命令出包 | 需要完整 Gradle 工程 |
| 个人开发友好度 | GDScript 上手快 | C# 更重 |

对"个人业余开发 + 2D RTS"这个组合，Godot 4 是明显更优解。

## 五、已实现的架构

代码在 `F:\KF\XJ\starcraft-android\`，共约 3500 行 GDScript。

### 5.1 分层设计

```
Main.gd  ← 表现层：渲染 + 触屏输入 + HUD（不做任何游戏逻辑）
   ↓ 读取
World.gd ← 模拟层：经济 / 建造 / 战斗 / AI / 胜负判定
   ↓ 使用
Unit.gd / Building.gd  ← 数据层：纯逻辑对象（RefCounted，不是 Node）
   ↓ 依赖
Grid.gd  ← 空间层：24px 格网 + A* 寻路
GameData.gd ← 数据表：3 种族 / 15 兵种 / 12 建筑 / 伤害矩阵
GenTex.gd  ← 程序化贴图：所有美术用代码画出来
```

**最重要的架构决策：逻辑与渲染彻底分离。**

`Unit` / `Building` / `World` 全部是 `RefCounted` 纯数据对象，**不给每个单位建 `Node`**。
渲染由 `Main.gd` 在单次 `_draw()` 里批量绘制。
这是 RTS 能撑住几百个单位的关键——如果每个兵一个 Node，几百单位就会掉帧。

### 5.2 关键技术点

- **寻路**：24px 格网，A* 八方向（禁止斜穿墙角），octile 启发函数，拉绳平滑（视线检测删中间点）。
- **邻域查询**：96px 空间哈希桶，避免 O(n²) 遍历。
- **伤害系统**：3 种伤害类型（普通/爆炸/冲击）× 4 种护甲类型（轻/中/重/建筑）的倍率矩阵。
- **单位分离**：互相推开，防止堆叠成一坨。
- **AI**：经济运营 → 科技 → 按波次进攻，带难度缩放。

### 5.3 触屏操作方案

```
轻点                → 选择己方单位 / 切换选中建筑
选中后轻点地面      → 移动；点敌人 → 攻击；点矿 → 采集
长按(>0.22s)拖动    → 平移镜头
快速拖动            → 框选
左下虚拟摇杆        → 平滑推镜
双击                → 近/远视野切换
```

## 七、开发中修掉的 4 个实质 bug

这些是"看起来能跑、其实不能用"的类型，值得记录：

1. **训练出来的兵会凭空消失**
   `Building._tick_queue` 自己把完工条目出队了，`World` 拿不到就没生成，资源也没扣。
   修法：`Building` 只负责倒计时 + 暴露 `ready_to_spawn()` / `pop_head()`，由 `World` 结算后再出队。

2. **下达攻击移动后部队永远站在原地**（最严重）
   `_update_combat` 找不到目标就 `return`，攻击移动的单位既没目标也不移动，永久卡死。
   修法：无目标时朝 `forced_target_pos` 继续推进——这是 RTS 的关键行为。

3. **寻路失败会清空已有路径**
   A* 返回空时把 `u.path` 覆盖成空数组，导致走到一半的单位卡住。
   修法：失败时不覆盖已有路径。

4. **AI 暴建 18 座建筑 / 首波永远不来**
   `_ai_produce` 每轮循环都触发建造；进攻阈值增长快于部队增长。
   修法：提前 return + 数量上限；首波时间 40s → 105s；双方对等开局。

## 八、如何运行与打包

### 环境（本机已就绪）

- Godot **4.7.2**：`F:\godot\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64_console.exe`
- 导出模板：项目内 `Godot/export_templates/4.7.2.stable/`（426MB，含安卓三件套）
- JDK 17：`C:\Program Files\Eclipse Adoptium\jdk-17.0.18.8-hotspot`
- Android SDK：`C:\Users\XiaoXin\AppData\Local\Android\Sdk`

### 常用命令

```bash
cd F:/KF/XJ/starcraft-android
GODOT="/f/godot/Godot_v4.7.2-stable_win64.exe/Godot_v4.7.2-stable_win64_console.exe"

# 跑逻辑测试
"$GODOT" --headless --path . --script res://tests/Smoke.gd

# 跑桌面渲染截图
"$GODOT" --path . --script res://tests/Shot.gd

# 导出安卓 APK
"$GODOT" --headless --path . --export-debug "Android"
# 产物：build/xinghai-zhanhuo.apk
```

### 装到手机

```bash
adb install -r -t build/xinghai-zhanhuo.apk
adb shell am start -n com.xinghai.zhanhuo/com.godot.game.GodotAppLauncher
```

> 注意入口 Activity 是 **`GodotAppLauncher`**（别名，`exported=true`），不是 `GodotApp`（`exported=false`，直接启动会失败）。

## 九、版权边界（重要）

当前实现是**完全干净的**：

- 引擎：Godot（MIT）
- 美术：`GenTex.gd` 全部用代码画（六边形晶体、地面砖、软光斑），**零外部素材**
- 数值：自研平衡，不照抄原版表格
- 命名：`星海战火` / 人族·自治联盟 / 虫族·虫巢意志 / 神族·达拉姆

**红线**：绝不能打包原版 MPQ 里的贴图、音效、过场动画。合规公式 = 自研引擎 + 自研美术 + 自研数值。

## 十、下一步路线

已完成的里程碑：**M0（导出 APK）→ M1（单位移动）→ M2（经济循环）→ M3（战斗）→ M4（触屏手感）→ M5（AI 遭遇战）**

剩余：

- **M6 局域网联机** —— 需要 lockstep 确定性同步。
  ⚠️ 必须从架构层面设计：所有随机数走同一个种子、浮点运算要可复现、指令按帧对齐。
  当前代码用的是 `float` 和 `randomize()`，**上联机前必须先改成定点数 + 确定性随机**，否则后期返工成本极高。
- **M7 三族完整对战** —— 补齐兵种、科技树、平衡性打磨。
- **美术升级** —— 目前是程序化几何图形，属于"能玩但不好看"。若要上架需要替换为正式美术。
- **发布准备** —— 正式签名密钥（当前用 debug keystore）、应用商店素材、隐私政策。
