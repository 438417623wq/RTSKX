## 二、为什么「像 WC3」不等于「用 WC3 的锁步」

WC3 用的是**确定性锁步**（所有端跑同一份模拟，只同步指令）。它确实是那个年代的经典设计，
带宽极小、天然带回放。但**它的臭名也是从这儿来的**：

- 著名的 **「desync / 掉线」** —— 两端模拟只要有一帧不一致，之后越走越远，
  玩家看到的是「队友的单位飘到地图外面」「我这显示打死了他那还活着」；
- 而且**不会报错**，只会静默分叉。

本项目踩不起这个坑，理由在上一轮方案里已经写清楚：

1. `World.step()` **吃全局 `randf()`** —— 地图生成、AI 决策都在用。改成确定性 RNG
   要动地图生成器与 AI 两处，回归面极大。
2. **arm64 真机与 x86_64 模拟器混联时浮点可能不一致** → 静默分叉。
   这和项目里踩过的「菌毯没铺 → 虫族 AI 变笨」「河道被岩石堵死 → 两岸孤岛」是同一类坑：
   **不报错，只是行为悄悄变了。**
3. 项目已经「逻辑与渲染彻底分离」，`World` 是纯数据对象 → 序列化成本低。
4. 局域网（同一 WiFi，RTT < 10ms）带宽完全够用。

> **所以「完善」体现在哪？**
> 体现在**体验层**：房间发现、大厅槽位、地图 / 难度选择、聊天、准备与倒计时、
> 对局中聊天 / 投降 / 暂停、断线提示。
> 而不是把「浮点必须完全一致」这个无底洞背到身上。

## 三、分期路线图

| 期 | 内容 | 交付判据 |
| --- | --- | --- |
| **M4a** | **地基**：类型索引表 + 世界状态编解码（`PackedByteArray`，零每帧分配）+ 协议包头与版本 | 往返一致（编码 → 解码 → 逐字段相同）；300 单位快照 < 12 KB；复用 buffer 时**不增长分配** |
| **M4b** | **最小可玩**：ENet 直连 + 手动输 IP + 2 人 + 指令上行 + 快照下行 + **迷雾过滤** | 两台设备能真的对打一局（方案原定判据） |
| **M4c** | **体验对齐 WC3**：UDP 广播发现房间 + 大厅（槽位 / 地图 / 难度 / 聊天 / 准备 / 倒计时）+ 对局中聊天 / 投降 / 暂停 + 断线提示 | 不填 IP 也能找到房间；大厅能聊天能准备；对局中能投降 |
| **M4d** | 后补（明确不在 M4 范围）：观战、回放、断线重连、公网 / 匹配 | — |

**为什么 M4a 单独一期**：它**不需要网络就能测**。项目已有的无头测试基建可以直接覆盖
「往返一致 / 尺寸上限 / 零分配」，而一旦掺进 ENet，无头测试就只能靠两台进程互连，
复杂度和不确定性都上一个台阶。先把地基用纯函数钉死，后面调协议才不会一动就崩。

## 四、协议设计

### 4.1 包头

```
[u8 type][u8 proto_ver][payload]
```

`proto_ver` 不匹配 → 直接 `BYE` 并提示「版本不一致」。**不能靠"大概能跑"** ——
版本不一致时的症状是「单位乱飞」，比连不上更难查。

### 4.2 消息类型

| 值 | 名字 | 方向 | 内容 |
| --- | --- | --- | --- |
| `0x01` | `HELLO` | C → H | 版本、玩家名 |
| `0x02` | `WELCOME` | H → C | 版本、我的 owner、双方种族、地图尺寸 / 预设、**随机种子** |
| `0x03` | `CMD` | C → H | 指令序列（移动 / 建造 / 训练 / 技能 / 编队） |
| `0x04` | `SNAPSHOT` | H → C | 世界状态（见 4.3） |
| `0x05` | `CHAT` | 双向 | 文本 |
| `0x06` | `PING` / `PONG` | 双向 | RTT 测量（大厅里显示延迟） |
| `0x07` | `BYE` | 双向 | 主动退出 / 版本不符 |

**地图随机种子必须由主机下发。** 两端各自生成地图的话，只要有一格不一致，
客户端就会看到单位「穿墙」—— 因为服务端认为那里是平地。

### 4.3 快照布局（定长为主）

```
u32  tick
f32  elapsed
i8   winner            -1 = 未结束
--- 双方全局 ---
  ×2: u32 minerals, u32 gas, u16 supply_used, u16 supply_cap
--- 单位 ---
u16  count
  ×count: u32 id, u16 type_idx, u8 owner,
          f32 x, f32 y,
          f32 hp, f32 shield,
          u8 facing(0..255 → 0..TAU), u8 mode_idx, u8 flags
--- 建筑 ---
u16  count
  ×count: u32 id, u16 type_idx, u8 owner,
          f32 x, f32 y, f32 hp,
          u8 progress(0..255), u8 flags, u16 queue_len
--- 资源节点 ---
u16  count
  ×count: u16 idx, f32 amount        # 位置由 seed 重建，只发会变的量
--- 迷雾 ---
u32  vis_len + 位图                 # ★按**这个客户端**的可见性过滤后发
```

### 4.4 三条关键取舍

**① 只发 int 的 `type_idx`，不发字符串。**
`"marauder"` 一个名字就 8 字节，300 个单位就是 2.4 KB/帧。

**② `type_idx` 表从 `GameData._BASE_*` 构建，不读模组改过的 `UNITS`。**
否则客户端装了一个模组、主机没装，**索引整体错位** ——
症状是「我的陆战队员变成了攻城坦克」，而且不报错。
（M3 已经禁止模组新建条目，所以基础键集是稳定的。）

**③ 迷雾按客户端过滤后再发。**
主机广播完整世界状态的话，客户端只要解包就能看到全图 —— **等于内置作弊**。
代价是主机要为每个客户端维护一份可见性过滤，且**迷雾外的单位不能发坐标**
（发了就能被推断出来）。
**这条在实现顺序上必须排在很前面** —— 后补的话整个快照格式都要重写。

## 五、四个风险与对策

### 风险 1：迷雾被绕过

见 4.4 ③。另外：**小地图上的「已探索但当前不可见」区域**也要跟着过滤，
否则客户端能通过小地图看到敌方基地布局。

### 风险 2：序列化每帧分配

`World` 现在**没有任何序列化方法**。几百个单位 × 每 100ms 一次，
如果每帧 `to_dict()` 造新字典，GC 压力会让手机掉帧。

**对策**：复用同一个 `StreamPeerBuffer` 实例，只 `clear()` 不 `new()`；
编码前先 `resize` 到估算容量，避免反复扩容。
`tests/Net.gd` 里钉一条断言：**连续编码 1000 次，buffer 的 `size()` 不增长**。

### 风险 3：客户端手感

主机权威 = 客户端操作要等一个来回。局域网 RTT < 10ms，加上 100ms 快照间隔，
平均约 35ms —— 点一下地面，单位 35ms 后才动，**在手机上能感觉到**。

**对策**：M4b **先不做预测**，先保证「能打起来」，再调手感。
客户端本地**乐观执行**（立刻播移动指令的动画 / 单位立刻起步），
下个快照到达时硬同步位置。这样「看起来立刻响应」而不用写预测模拟。

### 风险 4：指令与快照的时序

客户端在第 N 帧下的指令，主机在第 N+2 帧才收到并生效，快照回来已经是 N+5 帧。
如果客户端「乐观执行」之后收到的是**旧快照**，单位会**往回跳一下**。

**对策**：客户端记录「本地乐观指令的序号」，快照里带主机已处理的指令序号，
只对**序号之后**的本地指令保持乐观位置。M4b 先简化：**乐观位置只保留 150ms**，
超时或收到新快照就完全交给服务端。

## 六、验证纪律

### 无头能测什么（M4a 全部）

| 断言 | 说明 |
| --- | --- |
| **往返一致** | 构造世界 → 编码 → 解码到另一个世界 → 逐单位 / 逐字段比对 |
| **尺寸上限** | 300 单位 + 60 建筑 + 80 资源节点的快照 < 12 KB |
| **零分配** | 连续编码 1000 次，buffer `size()` 不增长（钉死风险 2） |
| **字节确定性** | 同一状态编码两次，字节完全相同（否则「快照比对」做不了） |
| **type_idx 稳定性** | 索引表从 `_BASE_*` 构建；装模组后索引不变 |
| **版本不匹配** | 改 `PROTOCOL_VERSION` 后，旧包被拒绝并给出明确原因 |

### 无头测不了什么（必须靠 M4b 的真机验证）

- ENet 实际连通（`--headless` 下可以起两个进程互连，但脚本复杂度高，M4b 再补）
- 客户端手感（只能靠眼睛）
- 迷雾过滤的**实际观感**（「我看不到敌人在哪」必须真的看不到）

### 沿用既有约定

1. 新增 UI 一律走**纯函数坐标 + 命中表**，让无头测试覆盖。
2. 新增设置项要有断言钉住「改了它，行为真的跟着变」。
3. 每期结束跑 `bash tests/run_all.sh full`。
4. **测「某东西做不到」必须配阳性对照**（M3 的三次回退验证是范例）。
